# Rulings, findings and deferred items from building ALU-FIFO

These are the notes I kept while building the design and while fixing what the final review found, lightly reworded. A *ruling* is a decision that
departs from, or fills a gap in, the spec or my working plan; a *finding* is something measured or discovered that shaped one. "Task N" is the step of
that plan a note belongs to; the plan isn't kept in this folder. The spec stays the authority: docs/superpowers/specs/2026-10-19-alu-fifo-design.md.

## Rulings

- Ruling: no git repo at the time, so a passing `make` gate stood in for each commit; the notes carry the gate command, not commit ranges — cost if wrong: none (I can `git init` later).
- Task 1: Ruling: self-test loop lives in scripts/rules_selftest.sh, not inline in the Makefile — Make quoting; same behaviour — cost if wrong: none
- Task 2: Ruling: TB drives/holds the source in a negedge always block and flushes via the main thread at posedge+0 boundaries — avoids driver/thread races — cost if wrong: Task 3 reset-in-traffic may need a flush flag
- Task 2: Ruling: known-answer table has 20 rows (plan listed 19 plus the SLL FFF0 row) and ka_row(19) is the SLTU-false row — plan table grouped AND/OR/XOR — cost if wrong: none
- Task 3: Ruling: +verilator+seed+N only accepts 1..2147483647 (aborts on 0 and 2654435769) — Makefile maps SEED to VSEED=(SEED%2147483646)+1 for Verilator's init seed; TB's +seed= is SEED unchanged — cost if wrong: two seeds could share an init seed (immaterial)
- Task 5: Ruling: a_conservation also requires each occupancy model to agree with that FIFO's empty/full flags — models are built from top wires, so a fault only on a FIFO instance pin (dropped result) would otherwise be invisible to a_lockstep and a_conservation; still implies the spec's property — cost if wrong: one extra conjunct
- Task 6: Ruling: fixtures hold only v_user+v_line records of a real coverage.dat (16 KB each, not 150 KB) — parser needs nothing else — cost if wrong: none

- Task 7: Ruling: mutants.py takes vflags/rtl/verif/sim-args from the Makefile (one source of truth) and requires ALL intended labels to fire, not any — stricter than 'among those fired' for multi-label mutants — cost if wrong: a mutant may need its intended list trimmed
- Task 7: Ruling: M02/M03 are multi-edit (FIFO guard AND the top's gating removed) because each single edit is equivalent through alu_fifo_top; M04 is full-tied-low (the observable effect of a missing wrap bit) — cost if wrong: none
- Task 9: Ruling: split synthesis checks in two scripts — scripts/synth.ys (check-rtl, no-latch, no-tribuf, then mapping, writes build/synth.v) and scripts/netlist_check.ys (reads build/synth.v back: check-assert, all-mapped, no-lpflow) — the post-mapping checks cannot be triggered from RTL, so they are tested on hand-made netlists (lesson from an earlier project: run RTL-unreachable checks on hand-made inputs); also checks the artifact, not the in-memory design — cost if wrong: one extra yosys run per make synth

- Task 9: Ruling: abc gets -D 10000 (CLK_PERIOD_NS*1000) with the pruned liberty; no -constr file (no driving cell/load in synthesis) — spec 6.2 names only -D — cost if wrong: synthesis timing optimism is not modelled; STA/PnR with the SDC measures timing
- Task 10: Ruling: Makefile exports CLK_PERIOD_NS/CORE_UTILIZATION and a build/period.stamp makes the netlist rebuild when the period changes (it is not a file) — cost if wrong: none
- Task 11: Ruling: sky130hd.pdn.tcl is the OpenROAD distribution's (met1 followpins + met4/met5 stripes), not the copy from Full-Adder — Full-Adder's is a 'minimal PDN for a tiny demo' with met2 stripes every 5.44 um; with it detailed_placement failed (DPL-0036) on exactly the 105 mux4_2 cells (reproduced on a 12-cell netlist; rails-only PDN placed them; the met2 stripes were the trigger; the exact mechanism was not identified) — cost if wrong: platform dir differs from Full-Adder's in one file, documented in sky130hd.vars

- Task 12: Ruling: spec 6.5 says a failing setup may be fixed by changing CLK_PERIOD_NS; the data says the period is not the lever (10.5 and 11.0 ns were worse), so CLK_PERIOD_NS stays 10.0 and repair_timing gets a 0.3 ns setup margin as the flow default (smallest tested value that closes) — cost if wrong: the margin is a tested value not an optimum; area/power change slightly; the 10.0 ns margin-0 result is kept in docs/results
